
1. Цель A/B-теста

Цель A/B-теста - сравнить две версии модели машинного обучения для предсказания дефолта клиента по кредитной карте.

В тесте сравниваются:

- v1 - текущая модель, используемая в проекте
- v2 - новая версия модели, которую планируется проверить

Текущая модель v1 это модель логистической регрессии.
Новая модель v2 может быть RandomForestClassifier, которая потенциально лучше определяет клиентов с риском дефолта.

Главная задача теста заключается в том, чтобыпонять, стала ли новая модель лучше находить клиентов, которые могут допустить дефолт, и не ухудшилось ли качество предсказаний в целом.

2. Постановка A/B-теста

Пользователи случайным образом делятся на две группы:

50%  контрольная группа A - модель v1
50%  тестовая группа B - модель v2

Контрольная группа A:

Контрольная группа получает предсказания от текущей модели v1.

Эта модель уже используется в проекте и является базовой версией для сравнения.

Тестовая группа B:

Тестовая группа получает предсказания от новой модели v2.

Новая модель проверяется на тех же типах входных данных, что и текущая модель.

3. Способ разделения трафика

Трафик предлагается делить случайным образом в пропорции 50/50.

Например:

- каждый новый запрос от пользователя получает случайное значение
- если значение попадает в первую половину диапазона, запрос отправляется в модель v1
- если значение попадает во вторую половину диапазона, запрос отправляется в модель v2

Такое распределение позволяет сравнивать модели в одинаковых условиях.

Важно, чтобы группы были похожи между собой по основным признакам:

- размер кредитного лимита
- возраст клиента
- история платежей
- сумма задолженности
- сумма предыдущих платежей

Если группы будут сильно отличаться, результаты теста могут быть некорректными.

4. Продолжительность теста

Рекомендуемая продолжительность A/B-теста - 2–4 недели.

Такой срок нужен, чтобы:

- собрать достаточное количество наблюдений
- избежать случайных колебаний в данных
- учесть разные дни недели
- получить более устойчивые результаты.

Если заявок мало, тест можно продлить до момента, пока в каждой группе не будет достаточно объектов для сравнения.

Минимальное условие завершения теста:

- в группе A и группе B собрано достаточно наблюдений
- по каждой группе можно рассчитать F1-score, Precision и Recall
- результаты можно сравнить статистически

5. Основная метрика

Основная метрика A/B-теста: F1-score для класса дефолта, класс дефолта - это класс 1.

F1-score выбран основной метрикой, потому что он учитывает сразу две характеристики модели:

- Precision - насколько точны предсказания дефолта
- Recall - какую долю реальных дефолтов модель смогла найти.

6. Дополнительная метрика

Дополнительная метрика:

Recall для класса дефолта

Recall показывает, какую долю клиентов с реальным дефолтом модель смогла правильно определить.

Для банка Recall важен, потому что пропущенный дефолт может привести к финансовым потерям. Если модель не заметила рискованного клиента, банк может принять неправильное решение по кредитному лимиту или одобрению продукта.

Поэтому новая модель v2 будет считаться полезной, если она увеличивает Recall для класса `1`, но при этом не приводит к сильному падению Precision.

8. Метод статистического анализа

Для анализа результатов можно использовать z-test для сравнения долей.

Этот тест подходит, потому что многие показатели в задаче классификации можно рассматривать как доли:

- доля правильно найденных дефолтов
- доля точных предсказаний дефолта
- доля ошибок
- доля клиентов, отнесённых к классу риска

9. Доверительные интервалы

Для каждой метрики нужно построить доверительный интервал, уровнем доверия 95%

Это значит, что мы оцениваем диапазон, в котором с высокой вероятностью находится истинное значение метрики.

Для каждой модели можно построить доверительный интервал:

- для F1-score
- для Recall

Если доверительные интервалы моделей сильно пересекаются, то нельзя уверенно сказать, что новая модель лучше.
Если доверительный интервал новой модели находится выше или показывает устойчивое улучшение, это аргумент в пользу внедрения v2.

10. Критерий успешности теста

Новая модель v2 считается успешной, если выполняются следующие условия:

1. F1-score для класса дефолта у v2 выше, чем у v1.

2. Recall для класса дефолта у v2 выше или не ниже, чем у v1.

3. Precision не падает критически.

4. Разница между моделями статистически значима.
